## Qué aprende y qué damos nosotros
El agente investigador DA a ambos brazos el mismo objetivo de alto nivel y una clasificación de 5 subobjetivos: store, update, retrieve, erase y skip. Para erase se exige el identificador correcto visto en list_memories (capa de seguridad no aprendida); para cambios se aporta el texto antiguo/nuevo. Ambos tienen acceso a las descripciones reales de las herramientas. El predictor **aprendido** estima mediante observaciones de llamadas reales y una comprobación de objetivo hecha únicamente sobre salidas MCP qué acción entre noop, remember, recall, list_memories y forget completa cada objetivo. Memorizar para cada par (tipo de objetivo, acción) aciertos/total y coste en número de tool calls; elegir máximo posterior Beta(1,1) (1+aciertos)/(2+ejecuciones) menos penalización 0,02 por llamada media, empate fijo orden: noop, recall, remember, forget, list_memories. No exponerle estado interno SQLite, truth futura ni respuestas del benchmark OOD. Esta es una memoria de utilidad condicionada por objetivos **predefinidos**, NO el controlador original EventEffects de F10-P, ni aprendizaje libre desde texto. Declarar explícitamente que este estudio NO prueba trasladar ese mismo algoritmo sin cambios.

Brazo **DOCS**: política competente usando la semántica documentada: store/update=>remember, retrieve=>recall, erase=>list_memories seguido de forget con IDs explícitos, skip=>noop; sin lecturas adicionales si la herramienta ya confirma éxito. Brazo **LEARNED**: elección por estadísticas arriba, mismos argumentos y seguridad. Brazo diagnóstico **SHUFFLED**: mismos ensayos TRAIN, pero resultados de éxito permutados dentro del conjunto de registros TRAIN antes de aprender los contadores (semilla 311900+r). Ningún brazo debe usar SQLite directamente para elegir acciones ni fingir resultados. Evaluador externo puede inspeccionar estado tras la sesión, separadamente de las decisiones.
