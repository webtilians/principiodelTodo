## B. Confirmación INDEPENDIENTE F12-U: ruptura de prefijo a nivel de _input_ids

F12-T indicó `PREFIX_PATH_CAUSAL_SIGNAL`: tras `O21-disabled` y reutilización de contexto, `q2`; al impedir `kv_cache_seq_rm` positivo vía retorno False, `q0`. El experimento U NO intervendrá en el valor de retorno de `kv_cache_seq_rm`. En `llama-cpp-python v0.3.36`, el código `Llama.generate()` compara `_input_ids` con el próximo prompt tokenizado y llama `reset()` cuando el prefijo no coincide. Se prueba una **perturbación diferente** y precisa: ANTES del target, establecer temporalmente `Llama.input_ids[0] = -1` (token centinela fuera del vocabulario) solo en brazo `PREFIX_ZERO`, forzando `longest_prefix=0`. El motor debe resetear y reevaluar todo el target, sin modificar pesos, el texto del target, parámetros, la implementación del backend ni el retorno de sus operaciones KV. `input_ids[0]` es una vista Python de historial, no el KV físico; registrar que el token se reescribe por la evaluación de prompt y restaurar valor anterior si excepcionalmente se aborta ANTES de evaluación. Esta instrumentación es interna/no API estable. Si no se verifica ruta completa y SHA de tokens del target, resultado INVALID.

Todos los brazos reciben las **mismas 12 llamadas diagnósticas F12-S** `(O0-start,O0-disabled,O7-start,O7-disabled,O21-start,O21-disabled)×2`, después uno de dos últimos antecedentes `O21-disabled` / `O0-disabled`, después target `O21-start` (SHA congelado `b3a52c881af625e9a56166841a334998ec6a366bbb957cb1eabf3c23f099e105`).
