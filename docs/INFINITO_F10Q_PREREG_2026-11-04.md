# INFINITO F10-Q — MCP SQLite shadow — prerregistro 2026-11-04

Este protocolo se publica antes de implementar o generar datos nuevos. F10-P-C queda congelado. Objetivo: probar EventEffects del F10-P original frente a llamadas reales al protocolo MCP y consultas SQLite nativas, sobre datos exclusivamente sinteticos en una base temporal, sin modificar el producto.

Instrumento: servidor MCP separado con una herramienta sql_select de solo lectura que ejecuta SELECT con parametros en SQLite. Las operaciones P, S, R y X usan consultas SQL reales: P carga el bit publico; S recupera id de la ultima fila acreditada; R consulta su payload; X calcula 1-valor mediante SQLite. El adaptador traduce la salida visible SQL columns/rows a eventos value, ack y error. Los nombres de operadores, el objetivo y las consultas son definidos por los investigadores; no se afirma aprendizaje libre de semantica SQL.

Cuatro replicas. TRAIN seeds 29100000+10000*r+j, j=0..127; cuatro variantes por mundo; 512 casos por replica, dos programas por caso, 1024 ejecuciones por replica. Programas de TRAIN elegidos por RNG 291700+r entre P,PX,SR,SRP,PXP,SPX,SRR,X. SRX excluido TRAIN. Cinco brazos EventEffects con el MISMO historial de llamadas: E100 salidas completas, E50 50% de omisiones RNG 291800+r, E0 sin salidas, E_noX sin respuesta X, E_shuffleX con bits X permutados RNG 291900+r. Controles diagnosticos Frozen_F10P (snapshot original SHA del run 41888234405) y Zero. Congelar cinco snapshots SHA antes de crear OOD.

OOD seeds 29400000+10000*r+j, j=0..127, cuatro variantes U_before,U_after,S_before,S_after, 9/11 filas SQLite. Solo MEMORY+FLIP1. Challenger contradictorio mas reciente no acreditado salvo S_after, donde esta acreditado. j modulo 8=0: ninguna fila acreditada. j modulo 8=1: payload ganador NULL. Esos 32 mundos/rep deben generar abstencion, no respuesta inventada. Los otros 96 mundos/rep son validos. Por replica: 384 casos validos y 128 casos de abstencion. Confirm seeds 29300000+ quedan sellados.

Comparar E100 con E0 y E_noX sobre los mismos casos; intervenir SQL X como identidad y SQL S sin filtro de acreditacion, manteniendo programas congelados. 2000 remuestreos bootstrap por 96 mundos base/rep, agrupando cuatro variantes, RNG 295000+100*r+offset. G0: 1024 TRAIN, al menos 1000 llamadas MCP, cero SRX, snapshots SHA y rechazo de INSERT por endpoint, 4/4. G1: E100 valido >=85%, limite inferior IC95>75%, estratos n/fuente/variante >=75%, seleccion SRX >=90%, 3/4. G2: E100-E0 y E100-E_noX >=20 puntos cada una, CI inferior>0, 3/4. G3: caida por X identidad >=30 puntos y por ignorar acreditacion >=10 puntos, CI inferior>0, 3/4. G4: abstencion >=99% en casos invalidos, cero respuesta binaria en ellos, ninguna escritura de herramienta, 4/4. G5 diagnostico: E50 y Frozen_F10P >=85%. PASS solo si G0..G4, segun umbrales. Error tecnico INCONCLUSIVE. Fail cientifico conservar sin ajuste.

Auditoria separada reconstruye semillas, reparto, logs MCP, memoria congelada, resultados brutos y gates; no modifica estados. No abrir confirm ni reelegir hiperparametros despues de OOD. El servidor y los esquemas SQL de este laboratorio estan hechos por nosotros, aunque ejecutan un motor y un protocolo reales; un PASS no implicaria herramientas externas ni integracion automatica.
